# ADR 0008: Use strict canonical route paths

- **Status:** Accepted
- **Date:** 2026-10-19
- **Scope:** core HTTP router, `@streetjs/router`, and `@streetjs/gateway`

## Problem

StreetJS route definitions are normalized to paths without trailing slashes in
the core HTTP server, but equivalent behavior was not explicitly documented or
tested across the standalone router and gateway. Prefix and wildcard matching
could treat `/users/` as an empty descendant.

## Existing behavior

Core route registration already removed trailing slashes and core matching used
anchored patterns. The standalone router compiled the supplied definition and
the gateway used exact/prefix/wildcard matchers with different edge behavior.

## Decision

StreetJS uses a strict canonical path policy:

- `/` is the only canonical root path;
- route definitions in the standalone router are normalized by removing leading
  and trailing separators (except root);
- non-root request paths ending in `/` do not match in the standalone router or
  gateway;
- prefix routes require at least one descendant segment after `/`;
- query strings do not participate in path matching;
- no redirect is generated by the matcher.

This preserves the existing core behavior and makes the standalone and gateway
contracts explicit. Applications that want redirects can add middleware at the
HTTP boundary.

## Alternatives considered

1. **Treat `/users` and `/users/` as equivalent:** rejected because the current
   framework and client contract already use slashless canonical URLs.
2. **308 redirect:** rejected for pure routers; redirect policy belongs to the
   HTTP boundary and would be a separate behavior.
3. **Leave behavior undefined:** rejected; gateway/core differences already made
   equivalent URLs unreliable.

## Compatibility impact

Requests with non-root trailing slashes that previously matched gateway prefix or
wildcard routes now return no match. Core behavior was already strict. Route
definitions with trailing slashes passed to the standalone router are normalized
to the canonical form. Existing slashless routes are unchanged.

## Evidence

Standalone router, gateway static/prefix/wildcard, gateway property-based routing,
and core HTTP integration tests cover the policy. Router and gateway test suites
pass after the change.
